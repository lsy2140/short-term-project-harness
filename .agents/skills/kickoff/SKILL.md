# kickoff

목표: 코드 전에 무엇을 확인했고 담당자에게 무엇을 물을지 TASK.md 에 고정한다. 요구사항 정리는 답을 받은 뒤 `$prd` 가 PRD.md 에 한다. 고치는 파일은 TASK.md·eda_summary.md·`decisions/pending.md`(제외 항목)·PRD.md 11절(제출 초안) 뿐이다.

## 읽는 것
- `README.md`(과제 안내) · 최상위 파일 목록(`ls -la`, 깊이 2까지).
- 데이터는 `python3 scripts/eda_bootstrap.py <파일들> --out eda_summary.md` 요약만. 원본 통째 읽기 금지(AGENTS 1절). 대조는 `head -5`.
- 기존 코드가 있는 과제면 코드를 쓰기 전에 진입점·실행 명령·테스트 유무를 표로(`ls -la`, `grep -rn "__main__\|argparse" --include=*.py .`, `python3 -m unittest -v` 1회).

## 절차
1. 시각: 사람에게 시작·마감 시각을 묻고 TASK.md 머리 2행에 `시작: HH:MM · 마감: HH:MM` 으로 쓴다. 모르면 `__:__` 그대로(추측 금지).
2. P0 체크 10항목: ① 전체 과제문 ② 채점 항목 ③ 실격 조건 ④ 제출 형식 ⑤ entrypoint ⑥ 데이터 위치·스키마·크기 ⑦ 출력 스키마 ⑧ 필수 흐름 ⑨ 런타임 버전 ⑩ 포트·시작 명령·미리보기 경로(+패키지·인터넷·지속성). README 에서 확인한 항목은 `[x]` 와 줄 번호만(내용은 `$prd` 가 PRD 7·8 에 원문으로). 없으면 추측하지 않고 3절 질문 표로.
   - ④⑤ 제출 항목(파일·폴더·이름·형식·업로드 방법·마감 동작)은 README 원문 그대로 PRD 11 표에 초안(출처 `README L12`·상태 `[ ]`). README 에 없으면 3절 질문.
3. 질문 표(TASK 3, 열 `코드 | 질문 | 답 요지 | 시각 | 결과(PRD ID·Dnn)`). 인터뷰 목적은 PRD 구체화다 — 답이 PRD 6 업무 규칙·9 가정의 빈칸을 채우는 질문만 만든다.
   - R 행: README 의 "담당자에게 확인" 류 문구를 전부 그대로 복사한다.
   - C 행 후보: `eda_summary.md` 끝 `## 담당자 질문 후보` 의 단위 혼재·완전 중복·시각 형식(표기만 다르면 제외 목록). `없음` 이면 비운다.
   - D 행: 고정 2개(조합 조건 "통과해도 따로 보는 것" · 이름 겹침 "다른 팹·라인에도 같은 이름", README 가 답하면 0) + eda 의 자정 넘김·식별자+범주 열 조합.
   - A·B·E·F 행: `docs/stakeholder_interview.md` 카테고리 표대로 각 0~3개. README 가 답하면 0, 개수 채우기 금지.
   - 모호한 지점은 가정으로 적지 않고 질문으로 만든다('모름' 이 오면 `$prd` 가 PRD 9 가정으로). EDA 에서 본 임계값·날짜 경계·중복 키는 그 질문 옆에 경계 후보로.
   - 제외 목록(표기·식별자·IT·정답 자료·화면 배치)은 질문이 아니라 `decisions/pending.md` 항목 `불필요 — 데이터 결정`.
   - 전송·묶음·순서는 docs 가 정하고 사람이 보낸다. 이 스킬은 표만 만든다.
4. 한 문장 목표: TASK '한 문장 목표' 문형을 그대로 채운다(모르는 빈칸은 질문 표로).
5. 2행 Status 의 `TEMPLATE` 을 `ACTIVE` 로 바꾸고(백틱 유지) 머리의 `[끝]`·`[남음]`·`[대기]` 3줄을 채운다.
6. 답이 오면 `$prd`: 사람이 붙인 `답변 B2: …` 는 TASK 3 같은 행의 답 요지·시각에 옮긴다. 묶음 답을 다 옮기면 다음은 `$prd`(PRD.md 초안 → 사람 승인). 완료 조건(TASK 5)은 PRD 승인 뒤 `$plan` 이 채운다.

## 보고

- 꼬리 1줄은 AGENTS 7절.
