# task-breakdown

목표: 합의문을 **테스트 이름이 붙은 20분 단위 단계**로 바꾼다. 결과는 PLAN.md 4번(규칙표)·TASK.md 5번(완료 조건)의 재료이고, 테스트 이름이 곧 완료 조건의 증거 좌표가 된다.

## 입력
`DECISIONS.md` 0번 합의문, `TASK.md` 1~5번, README의 제출물 형식. 합의문이 없으면 먼저 `$exam-kickoff`·`$stakeholder-interview`를 권하고 멈춘다.

## 절차
1. 목표·수용 기준을 2줄로 재진술한다. 합의문과 다르게 읽히면 멈추고 묻는다.
2. 단계를 나눈다. 1번은 항상 **첫 완주**(입력→출력 파일→형식 확인→기록), 그다음 규칙 1개 = 단계 1개, 마지막은 동결·문서(README·DECISIONS·HANDOFF).
3. 단계마다 **테스트 이름**(`test_<규칙>_<상황>`)과 "먼저 FAIL을 볼 입력" 1개를 적는다. 테스트로 못 재는 단계는 `HUMAN_CHECK`로 표시하고 이유를 쓴다. 형식 위반·불일치 참조를 거부해야 하는 규칙은 `assertRaises(ValueError)` 단계를 따로 둔다.
4. 의존성은 단계 번호로 적고, 순서를 바꿀 수 없는 이유를 한 단어로 적는다(예: 키 정규화 → 중복 제거).
5. 합의문·README에 없어서 결정이 필요한 항목은 **누락 요구** 열에 적고 TASK.md 3번(열린 질문) 추가를 제안한다. 추측으로 채우지 않는다. 결정이 필요한 단계는 구현 시 코드에 `# 결정:` 주석을 남기도록 표시한다.
6. 20분을 넘길 단계는 둘로 쪼갠다. 분 합계가 남은 시간(`python3 scripts/timer.py`)을 넘으면 뒤에서부터 `생략 후보`로 표시한다.

## 출력 (표만, 10행 이내)
| # | 단계 | 테스트 이름 | 의존 | 누락 요구 | 분 |
|---|---|---|---|---|---|

마지막 줄: 1번 단계를 시작하는 위임 프롬프트 1개(목표 / 범위 / 제약 / 완료 조건 / 검증 5요소).

## 금지
- 코드·파일 작성(이 단계는 표만). README·합의문에 없는 기능을 단계로 넣기. "나머지 전부"처럼 검증할 수 없는 단계.
