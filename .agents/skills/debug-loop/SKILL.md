# debug-loop

목표: 고치기 전에 **재현**하고, 고친 뒤 **재현 테스트**로 잠근다. 재현과 진단을 섞지 않는다.

## 절차
1. **최초 실패 신호**: 긴 출력(`unittest -v`·서버 로그)은 전부 읽지 않는다. 오류를 종류별로 묶어 건수를 세고(`grep -c`), 시간순 **첫 번째** 실패만 고른다. 증상(뒤따른 오류)과 원인(첫 오류)을 구분해 적는다.
2. **한 줄 재진술**: 오류를 쉬운 말 한 문장으로, 의심 `파일:줄`과 그 줄이 하는 일을 적는다. 전제가 되는 입력·환경(Python 버전, 인코딩, 시간대)도 한 줄.
3. **최소 재현**: 입력 3행 이내(헤더 포함) · 실행 명령 · 기대 vs 실제를 표로. 담당자 피드백이면 담당자가 말한 값과 우리 출력값을 나란히 둔다. 재현이 안 되면 "재현 불가 — 필요한 정보: ___"로 멈춘다. 재현용 임시 입력(3행 CSV·셔플 사본·엣지 변형)은 `.tmp/`(gitignore)에 만들고 `out/debug/`·`data/`에 두지 않는다.
4. **가역적 검사 순서**: 되돌리기 쉬운 것부터(입력 값 확인 → 경계·결측·중복·형식 혼재 → 최근 변경(DECISIONS 4번·debug 폴더 note.md) → 환경) 원인 후보 3개와 확인 명령을 표로. 광범위 print 대신 최소 프로브 1개. 입력 파일은 수정하지 않는다.
5. **재현 테스트**: `tests/`에 `test_<규칙>_<상황>` 이름으로 추가하고 `python3 -m unittest -v`로 **먼저 FAIL**을 본 뒤 고친다(`$unit-test-starter` 형식). 원인이 "거부해야 할 입력"이면 조용히 보정하지 않고 `ValueError`로 명시 거부한다.
6. **기록**: DECISIONS.md 4번에 한 줄 — 무엇이 틀렸나 / 어떻게 알았나(테스트 이름·명령) / 조치(out/debug/NN/green.txt) / 같은 종류의 입력 1개 더. 수정한 코드 줄에는 `# 결정: <왜 이렇게>`를 남긴다.
7. **저장 위치**: 이 단계의 로그는 `python3 scripts/debug_dir.py NN_단계명`(예 `02_규칙_tz`)으로 만든 `out/debug/NN_단계명/`에 **5파일 상한**으로만 — `red.txt`(먼저 본 FAIL 원문) · `green.txt`(고친 뒤 PASS) · `verify.json`(숫자) · `decisions.txt`(`--decisions NN_단계명`) · `note.md`(결정이 필요했던 것만). 닫을 때 `python3 scripts/debug_dir.py --check` exit 0 확인.

## 출력 형식
| 단계 | 내용 | 근거(파일:줄·명령) |
|---|---|---|
표 뒤에 다음 행동 1개만 적는다.

## 금지
- 재현 전에 코드 수정. 테스트를 통과시키려고 테스트·기대값을 바꾸기(바꿔야 하면 먼저 말한다). 원인 추정을 사실처럼 쓰기(`확인 필요`로 표기).
- `out/debug`에 스냅샷(`*_before/`·`*_protected_before.json`)·입력 복사본·브라우저 프로필·중간 출력을 쌓기. 복구본은 1차 동결 `preflight --freeze` 1회뿐이고 임시물은 `.tmp/`다(`--user-data-dir=.tmp/chrome`).
