## 0. 원칙 — Operate 모드는 절제가 야심 (mode-operate.md)
- 운영 화면(대시보드·콘솔·폼)은 **먼저 그 분야의 작동하는 제품**이다. 쓰는 사람은 '세계관'을 알아채기 전에 모든 것이 어디 있는지 안다.
- 표현이 빌려주는 것은 네 가지뿐: 서체·팔레트·밀도·시그니처 한 수. 레이아웃·내비·컨트롤은 빌려주지 않는다 — 버튼·탭·입력·표는 쓰는 사람이 이미 아는 표준 컨트롤.
- 회색 화면 + 강조색 하나는 '절제'가 아니라 다듬지 않은 기본값이다. 색은 일을 한다: 상태색·데이터 계열·선택·셸(상단 바).
- 마감선은 그 분야 최고 제품: 정렬된 그리드·일관된 간격·실제 타입 스케일·분명한 위계. 시그니처는 이미 깨끗한 화면 위에 얹는다.
- 자가 점검: 제품명을 가리고도 그 분야의 제품으로 읽히나 / 이 화면으로 작업을 끝낼 수 있나 / 표준보다 깨끗하고 조금 더 개성 있나.
- 우리 키트: 세계관 = tokens.css 브랜드 블록 1곳, 시그니처 = `.bezel` 1곳(히어로·미리보기). 나머지는 표준 컴포넌트.

## 1. craft-floor — 검증 항목과 거부 패턴
**검증(의도가 아니라 만들어진 결과를, 한 번의 렌더에서 함께 본다)**
- 대비: 본문·입력 안내 글자 ≥ 4.5:1, 큰 글자 ≥ 3:1. 색 면 위 보조 글자는 회색이 아니라 그 색조로 → ui_check `contrast (tokens)`
- 깊이: 그림자는 오프셋 + 부드러운 블러. 오프셋 0 의 색 후광은 장식 → `--shadow-1/2` 만
- 간격: 묶음은 촘촘히, 묶음 사이는 넓게, 제목 위 > 제목 아래. 계산된 값을 읽는다
- 타입: 본문 65~75ch, 디스플레이 ≤ 6rem, 자간 바닥 -0.04em, 스케일·굵기 단계가 눈에 띄게. 실제 문구를 모든 폭에서 돌려 넘치는 것을 고친다
- 모션: 쓴 순간 하나. 섹션마다 같은 등장 효과 금지 → 우리는 진입 모션 0, hover·active 만
- 상태: hover·disabled·loading·error·empty + 실제 내용·작동하는 컨트롤·반응형·키보드 포커스
- 브라우저 표면: 선택 색·캐럿·스크롤바·포커스 링·밑줄 오프셋·tabular 숫자 — 그리지 않은 부분도 팔레트에서
- 문구: 제품의 언어. 컨트롤은 동작을 이름으로, 오류는 문제와 복구를 이름으로
- 커버리지: 요구사항 전부가 있고 몇 초 안에 찾아진다
**거부(분야의 기본값이지 금지는 아님 — 요구가 있으면 쓸 수 있다. 단 아이브로는 금지)**
- 같은 크기의 아이콘+제목+글 카드로 페이지를 짜기. 카드는 게으른 컨테이너, 카드 속 카드는 항상 틀림
- 히어로 지표 템플릿(큰 숫자·작은 라벨·보조 수치·강조색). 운영 화면의 KPI 행은 실제 숫자+단위+전일 대비일 때만
- 제목 위 아이브로·키커(금지), 정보가 없는 섹션 번호 01/02/03, 중단이 필요 없는 작업의 모달
- 그라디언트 글자, 장식용 글래스·블러, 카드·알림의 1px 초과 색 보더(키트 `.eq` 상태 보더는 색+글자 쌍이라 예외), 네오브루탈이 아닌데 하드 오프셋 그림자
- 내용 대신 스파크라인·진행 링·둥근 사각형으로 자리 채우기, '기술적' 분위기용 모노, 이모지 아이콘, 사진 대신 기하 마스크
- 자간은 -0.04em 에서 멈춘다. 엘리베이션은 보더 또는 그림자 하나(1px 보더 + 넓은 그림자 = 유령 카드). 카드 반경 12~16, 필은 작은 컨트롤만
- 주장·설정값은 주어진 사실에서. 예시 값은 예시라고 표시한다

## 2. audit — 점검 순서 (고치지 않고 기록한다)
순서는 **위계 → 간격 → 상태 → 문구 → 반응형**. 각 차원 0~4점, 합계 20.
1. **위계·접근성**: 대비 < 4.5:1, 제목 단계 건너뜀, 랜드마크·ARIA 누락, `div` 로 만든 버튼, 포커스 표시 없음, `alt`·`label` 누락, 오류 메시지 부실, reduced-motion 이 상태 변화까지 지우는 전역 kill
2. **간격·테마**: 토큰을 안 쓴 하드코딩 색·간격, 토큰 혼용, 테마를 바꾸면 안 따라오는 값
3. **상태·성능**: 레이아웃 속성 애니메이션, 무한 블러·그림자, `will-change` 남발, 루프 안 레이아웃 읽기, lazy 없는 이미지
4. **문구·구현 일관성**: 반복되는 구현 지름길, 디자인 시스템 이탈, 장식용·오해 소지 내용, 다른 제품과 바꿔도 되는 구조. 결정론적 발견(검사기)과 시각 판단을 분리하고 오탐은 오탐이라 적는다
5. **반응형**: 고정 폭, 터치 타깃 < 44px(WCAG 최소 24), 좁은 폭 가로 스크롤, 글자 확대에 깨짐, 브레이크포인트 없음, 터치에서 죽는 드래그
점수 띠: 18~20 우수 / 14~17 양호 / 10~13 보통 / 6~9 미흡 / 0~5 위험. 우리 ui_check 는 1·2·5 의 정적 절반을 맡는다.

## 3. critique — 비평 형식 (심각도·좌표·수정안)
- 머리에 실행 방식을 선언(캡처 있음/없음, 검사기 결과 있음/없음). 조용히 축소한 비평은 실패한 비평
- 먼저 **제품 고유성 판정**: 이름을 가리고도 그 분야의 제품으로 읽히나 — 통과/실패 + 근거
- 전체 인상 2~3줄 → 잘 된 것(유지할 것) → 우선 이슈 → 사소한 관찰 → 질문
- 우선 이슈 한 건 = `[P?] 이름 · 좌표(컴포넌트·파일:줄·CSS 선택자) · 영향(누가 어떻게 곤란한가) · 수정(구체 행동)`
- 심각도: **P0** 작업 불가(즉시) / **P1** 큰 어려움·WCAG AA 위반(릴리스 전) / **P2** 불편·우회 가능(다음 패스) / **P3** 다듬기(시간 남으면). P3 는 적게 — 긴 꼬리가 중요한 것을 묻는다
- 페르소나 2~3(이 화면을 쓰는 사람: 교대 운영자·설비 엔지니어·심사자)마다 붉은 깃발 1개
- 끝은 질문: 발견에 묶인 구체 질문 2개, 각각 선택지 2~3개(우선 이슈 3개 미만이면 '질문 생략: N건' 한 줄). 질문이 마지막 줄
- 피할 것: 영향 설명 없는 지적, 일반론 권고, 긍정 발견 생략, 전부 P0, 검증 안 한 오탐
- 우리 키트: 보고는 SKILL.md 절차 7 의 5줄로 압축, 위반 표는 DECISIONS.md 검증 로그에 붙인다

## 4. harden — 엣지·빈·오류·긴 문자열·느린 상태
- 극단 입력: 100자 넘는 이름·설명 / 빈 값·한 글자 / 이모지·RTL·결합 문자 / 백만·십억 단위 숫자 / 1000+ 행 목록 / 데이터 없음
- 오류: 네트워크 끊김·느림·타임아웃, API 400/401/403/404/429/500 각각의 화면, 검증 오류는 필드 옆에 구체적으로, 입력값 보존, 재시도 버튼
- 긴 문자열: 한 줄은 `text-overflow: ellipsis`, 여러 줄은 `-webkit-line-clamp`(키트 `.item .title` 2줄), 감쌀 곳은 `overflow-wrap: break-word`, flex/grid 자식에 `min-width: 0`
- 빈 상태: 무엇이 비었나 한 줄 + 왜 중요한가 + 다음 행동 1개(`.empty`). "결과 없음" 한 마디로 끝내지 않는다
- 로딩·느린 상태: 모양을 아는 목록·카드·표는 스켈레톤(`.skeleton`), 버튼 안은 스피너가 라벨을 대신하되 폭이 튀지 않게. 무엇을 불러오는지 말한다
- 동시 조작: 요청 중에만 제출 버튼 비활성(쉬는 중 비활성 금지), 10번 연타해도 1건
- 국제화: 번역이 30~40% 길어져도 깨지지 않게(고정 폭 금지), 날짜·숫자·통화는 로케일 포맷, UTF-8 고정
- 권한·읽기 전용 상태는 이유를 보여준다. 한 컴포넌트의 오류가 화면 전체를 막지 않는다
- 검증 순서: 긴 글 → 이모지 → 빈 데이터 → 1000행 → 오프라인 → 연타 → 오류 강제. 무엇으로 확인했는지(에뮬레이션·실기기)와 못 본 것을 적는다
- 우리 키트: `scripts/make_edge_cases.py` 로 엣지 입력을 만들고, 템플릿 상태 배너(ok/fallback/failed)가 실제로 바뀌는지 본다
