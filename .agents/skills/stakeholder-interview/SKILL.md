# stakeholder-interview

목표: README에 없는 **숨은 조건**(제외 대상·경계값·단위·시간대·우선순위·사용자·성공 지표·응답 모양)을 캐내고, 구현 전에 담당자가 확인한 합의문을 만든다.

## 질문 설계 규칙
- 해법 단어(자동화·AI·대시보드)보다 **업무 사실**을 묻는다. "뭘 만들면 되나요?"는 금지. README에 이미 답이 있는 것은 묻지 않는다.
- 순서: ① 최근 에피소드 ② 지금 방식(워크어라운드) ③ 성공을 아는 숫자와 현재 값 ④ 안 풀리면 누가 얼마나 손해 ⑤ 예외·제외·경계값·단위·시간대 ⑤-1 절대 나가면 안 되는 결과(그게 나가면 누가 어떤 손해를 보나) ⑤-2 실패·지연·데이터 없음일 때 화면/파일에 무엇을 보여야 하나 ⑤-3 이 업무는 몇 단계이고 이번에 자동화할 단계는 어디까지인가 ⑤-4 화면·API·파일의 응답 모양(목록만인지, 건수·요약이 붙는지, 열 순서) ⑥ 합의 확인.
- **첫 질의는 5~8개를 번호를 붙여 한 메시지로.** 한 번호에 한 주제, 질문마다 괄호로 왜 묻나 한 줄. 묶음 질문(한 번호에 둘)은 금지 — 담당자 AI 는 하나만 답하고 넘어갈 수 있다. 이후 되묻기는 1~2개씩("그 경우는 어떻게?", 번호는 `N-1`, `N-2`).
- 담당자가 모른다고 하면 **가정으로 기록**하고 틀렸을 때의 영향과 안전한 쪽(과소/과대 포함)을 적는다.

## 산출물
1. 답변은 `답변 N:` 번호로 받아 `TASK.md` 3번 표에 번호로 매핑(질문 번호 = 답변 번호, 시각 기록), 2번 가정 갱신.
2. `DECISIONS.md` 0번 합의문: 문제 / 지금 방식 / 성공 기준(숫자·현재값·측정처) / 만들 것 / 안 만들 것 / 제약.
3. 담당자에게 보낼 **합의 확인 메시지**(5줄 이내): "제가 이해한 내용입니다. 맞습니까? 다른 점이 있으면 알려 주세요."

## 응시자에게 돌려줄 것
- 복사해 보낼 질문 5~8개(번호, 괄호 안 '왜 묻나' 포함) · 되묻기 후보 2개. 메시지 틀은 `docs/프롬프트_예시.md` 5번(`python3 scripts/prompt.py 5`).
