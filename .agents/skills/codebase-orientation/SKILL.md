# codebase-orientation

목표: 낯선 코드를 **통째로 읽지 않고** 10분 안에 "어디서 시작하고, 어떻게 돌리고, 어디를 고치면 안전한가"를 좌표(파일:줄·명령)로 적는다.

## 절차
1. 구조: `ls -la`(깊이 2), `find . -name "*.py" | head -40`, `wc -l`로 크기순 정렬. 500줄 넘는 파일은 `head -60`·`grep -n`으로만 본다.
2. 진입점: `grep -rn "__main__\|argparse\|http.server\|HTTPServer\|app.run" --include=*.py .` → 실행 명령 후보. README·Makefile·`requirements.txt`가 있으면 명령을 **원문 그대로** 인용한다.
3. 실행·테스트: 후보 명령을 실제로 1회 실행(`--help`, `python3 -m unittest -v`)하고 결과를 PASS/FAIL/NOT_RUN으로 적는다. 포트·환경 변수는 `grep -rn "PORT\|0.0.0.0"`으로 찾는다.
4. 모듈 맵: 파일마다 역할 1줄 + 공개 함수 2개(`grep -n "^def \|^class "`), 데이터가 들어오고 나가는 지점(`open(`, `csv.`, `json.`)을 표시한다.
5. 안전한 첫 수정 지점: 테스트가 있는 함수 또는 출력 직전 단계 1곳. 입력 파일을 바꾸거나 전역 상태를 만지는 지점은 **위험**으로 표시한다. 기존 `# 결정:` 주석과 `raise ValueError` 지점을 모아 "이미 거부하는 입력" 목록을 만든다(없으면 "없음"이라고 적고, 첫 테스트는 거부 케이스부터 FAIL을 보게 제안).
6. 보고 뒤 TASK.md 1번(사실)에 실행 명령·진입점을, 2번(가정)에 역할 추정을 넣는다. 추정은 `추정`이라고 표시한다.

## 출력 (표만)
| 구분 | 파일:줄 | 내용 | 확인 명령·상태 |
|---|---|---|---|
구분 = 진입점 / 실행 / 테스트 / 모듈 / 입출력 / 첫 수정 지점 / 위험.

## 금지
- 파일 전체 `cat`. 파악 단계에서 코드 수정·리팩터 제안. 요청 범위 밖 폴더 탐색. README에 없는 기능 제안.
