# prd

목표: 요구사항을 PRD.md 한 곳에 ID(G 목표·R 기능·B 규칙·A 가정)로 고정하고, 사람이 승인(v1)한 뒤에만 `$plan` 으로 넘어간다. 인터뷰는 PRD 를 구체화하려고 하는 것이다. 코드는 쓰지 않는다. PRD.md 는 T1(A_core·단일 세션)만 쓴다 — B·C 는 읽기만, 바꿀 것은 ⑦ `@사람`.

## 입력
- `README.md`(과제 안내 원문), `TASK.md` 3절(질문 코드별 답 요지·시각), `eda_summary.md`(담당자 질문 후보 포함), `decisions/pending.md`(대기 중 결정).
- 답이 아직 없는 질문은 9절 가정으로 두고 멈추지 않는다.

## 절차 (`$prd` — 초안 v0)
1. 1·2절: 배경(최근 사례·지금 방식)과 목표를 답변 A·R 에서. 성공 기준은 규칙·형식·숫자로, README·답에 없으면 `확인 필요`(정답 목록·현재값을 담당자에게 요구하지 않는다).
2. 3·4절: 범위 안/밖은 README 와 답변 F. 밖에는 왜·대신 쓰는 것·다시 하려면 조건.
3. 5절 기능 요구: README 문장 하나 = R 행 하나(원문 인용, MUST/SHOULD 는 README 표기대로). 완료 조건은 테스트 이름(`test_<규칙>_<상황>`) 또는 HUMAN_CHECK.
4. 6절 업무 규칙: 판정·계산·제외·경계·중복·단위·시간대·정렬을 B 행으로. 출처 없는 규칙은 만들지 않는다 — 출처는 `README L__`·`답변 B2`·`가정 A01` 중 하나. EDA 경계 후보는 경계·예외 칸에, 사람 결정이 필요하면 pending 항목을 만들고 상태 `대기 Dnn`.
5. 7·8절: 입출력 형식(헤더·순서·인코딩)과 실행 환경을 README 원문으로. 8절에 이미 적힌 환경 메모(사전 체험·`preflight --env`)는 지우지 않는다.
6. 11절 제출: `$kickoff` 초안을 README 원문과 대조해 파일·폴더·이름·형식·확인 명령·출처 줄을 채운다. README 에 없는 제출 조건은 만들지 않는다(추측 금지, 모르면 TASK 3 질문). 승인 뒤 바뀌면 10절에 1줄.
7. 9절: 가정마다 '틀리면 깨지는 것·안전한 쪽'. '모름' 답은 여기로. 아직 묻지 않은 것은 질문 코드를 붙여 TASK 3절 추가 질문으로 제안.
8. TASK 3 결과 열에 답이 들어간 PRD ID(또는 Dnn)를 적고, 2행(버전 `v0`·출처 수)을 갱신한다.
9. 보고 = 사람 검토 포인트 5줄(가장 위험한 가정 2 / 출처가 약한 규칙 2 / 범위 밖으로 뺀 것 1) + 담당자에게 보낼 PRD 검토 요청 5줄 초안(`docs/stakeholder_interview.md` 4절 틀, PRD 3·5·6 요약). DECISIONS 0 송부 줄은 '아직 전송하지 않음'.

## 승인 ("PRD 승인")
- 사람이 회신 원문을 붙이면 다른 점을 본문에 반영한다. "PRD 승인" 이면 2행 버전을 `v1` 로·승인 시각 → 10절 v1 행 시각 → DECISIONS 0 에 PRD 송부·담당자 회신(시각·원문 그대로).
- 회신 전에 승인하라고 하면 그대로 하고, 나중 회신의 다른 점은 `$prd 갱신` 으로.

## 갱신 (`$prd 갱신`, `요구사항 갱신:` 이 올 때마다)
- 본문 행은 바꾸되 ID 는 유지, 바뀐 행 ID 옆에 `(v1.1)`, 2행 버전·갱신 시각도 올린다. 10절에 한 줄: 버전·시각·바뀐 ID·출처·영향(PLAN 4 task·테스트 이름).
- 영향 task 의 담당에게 알릴 한 줄(`@B: R04 열 순서 변경 → test_… 수정`)은 자기 work 파일 ⑦ 에(사람이 전달, 단일 세션은 보고에만). DECISIONS 0 '담당자 확인 기록' 에는 시각만.
- pending 결정이 나면 6절 상태 칸만 `D07 결정` 으로 바꾼다(내용은 DECISIONS 1 에만, 10절 불필요).
- 사람 승인 없이 규칙을 바꾸지 않는다. 담당자 답이 바뀌어 왔으면 먼저 `요구사항 갱신:` 으로 재진술(AGENTS 5절).

## 출력
- `PRD.md`(v0 → 승인 뒤 v1, 11 제출 포함) · 검토 포인트 5줄 · PRD 검토 요청 5줄 초안 · TASK 3 결과 열·추가 질문 제안. 꼬리 1줄은 AGENTS 7절.
- `$plan` 은 PRD 의 R·B·A ID 를 task 표 '입력'·'완료 조건' 에 그대로 쓴다.

## 금지
- 코드·테스트 작성. README·답변에 없는 요구 추가. 담당자에게 정답 목록·현재값 요구. 승인 전 `$plan`. 승인 뒤 10절 없이 본문 수정.
