# exam-kickoff

목표: 코드를 쓰기 전에 **무엇을 만들고 무엇을 만들지 않는지**를 문서로 고정한다.

## 절차
0. TASK.md 머리에 `시작: HH:MM`(사람이 말한 시각, 모르면 현재 시각)을 쓰고, 첫 보고에 `python3 scripts/timer.py --start HH:MM --loop 300` 과 `python3 scripts/next.py` 명령을 그대로 출력한다.
1. `README.md`(과제 안내)와 최상위 파일 목록(`ls -la`, 깊이 2까지)을 읽는다. 데이터 파일은 통째로 읽지 말고 `python3 scripts/eda_bootstrap.py <파일들>`을 실행해 `eda_summary.md`만 읽는다.
2. 제출물(파일명·형식·경로·헤더·정렬)과 평가 기준 문구를 **원문 그대로** 추려 TASK.md 1번(사실)에 넣는다. 출처를 적는다.
2-1. P0 10항목(+환경 1)을 README에서 찾는다: ① 전체 과제문 ② 채점 항목 ③ 실격 조건 ④ 제출 형식 ⑤ entrypoint ⑥ 데이터 위치·스키마·크기 ⑦ 출력 스키마 ⑧ 필수 흐름 ⑨ 런타임 버전 ⑩ 포트·시작 명령·미리보기 경로 ⑪ 패키지·인터넷·지속성(가능 여부). README에 없는 항목은 추측하지 말고 그대로 TASK.md 3번(열린 질문)에 올린다.
3. 모호한 지점을 TASK.md 2번(가정)과 3번(열린 질문)으로 나눈다. 질문은 `docs/담당자_인터뷰.md` 순서(에피소드→워크어라운드→정량화→비용→경계→합의)로 5~8개, 번호, 한 주제 한 질문, 질문마다 왜 묻나 한 줄.
4. TASK.md 4번(안 할 일)을 최소 2개 적는다. 5번(완료 조건)은 테스트 이름으로 쓴다.
5. 한 문장 목표를 TASK.md 맨 위에 쓰고 Status를 `ACTIVE`로 바꾼다. 목표 문장은 Quality Bar 5질문을 통과해야 한다: **무엇이 참이 되나**(끝났을 때 성립하는 사실) / **증거**(검증 명령·테스트 이름·출력 파일) / **수치 기준**(행 수·허용 오차·연속 통과 횟수) / **범위**(안·밖 각 1개 이상) / **중단 조건**(무엇이 나오면 멈추고 묻나). 이어서 자동화 대상 문장을 그 아래 줄에 쓴다: "나는 ___와 ___를 자동화한다. ___는 하지 않는다. 이유는 ___." 15분 안에 빈칸을 못 채우면 담당자에게 묻는다(`$stakeholder-interview`).
6. 사람에게 보여줄 것: 한 문장 목표 / 제출물 표 / 질문 5~8개 / 첫 완주 계획 3줄.

## 금지
- 코드 작성, 파일 생성(TASK.md·eda_summary.md 제외), 라이브러리 설치.
- README에 없는 요구를 추가하는 것.
