# rule-loop

목표: 규칙 1개 = 테스트 1개 = task 1개. 표 → 승인 → FAIL → 구현 → PASS → 발동 건수 → 기록. 고치기 전에 재현한다.

## ① 케이스 표 → 승인 → FAIL
- 대상 함수 시그니처와 규칙 문장(PRD ID·DECISIONS 1)을 인용한다. 규칙 문장이 없으면 묻는다.
- 기대값이 업무 결과를 바꾸는 선택(경계·자정·단위·제외·산식 등)에 기대면 사람 결정(`decisions/answers.md` 또는 pending.md 의 `[x]`)을 확인한다. 없으면 그 행은 빼고 pending.md 항목(`담당자 확인: 필요` + `담당자 질문:`)으로 먼저 올린다(AGENTS 5절).
- 승인 요청 첫 줄: `업무 규칙: 없음` 또는 `업무 규칙: D03(결정됨)·D07(대기)`. 대기 결정에 기대는 행은 `결정 대기 D07` 로만. 표 승인은 업무 규칙 결정을 대신하지 않는다.
- 최소 구성: 정상 2 · 경계 1(임계값과 같음·±1) · 결측 1(`''`·`NA`·`-`) · 중복 1. 거부 규칙이면 `assertRaises(ValueError)` 행.

| # | 유형 | 입력(3행 이내) | 기대 | 무엇을 시험하나 |
|---|---|---|---|---|

- 승인 뒤 `tests/test_<task>.py`(형식 `tests/test_template.py`). 케이스마다 `# 무엇을 시험하나:` 1줄, 입력은 코드 안(`data/` 의존 금지), 임계값 상수는 import.
- `python3 -m unittest -v tests.test_<task>` → FAIL/ERROR 원문을 보이고 `red.txt` 로. 처음부터 PASS 면 입력을 바꿔 FAIL 을 본다.

## ② 구현 → PASS → 발동 건수
- 다음 턴에 `core/<task>.py` 구현(설명문·`# 결정:` 은 AGENTS 1절 8·4절). 같은 명령으로 PASS → `green.txt`.
- 출력 확인: 존재·행 수·헤더·정렬·인코딩·`head -3`. 불변량(`입력 == 통과 + 제외`·키 중복·범위)은 한 줄 스크립트로 재계산.
- 발동 건수 표 `규칙 | 발동 행 수 | 예시 키`. 0건이면 `python3 scripts/make_edge_cases.py <csv> --out .tmp/<이름>/edge` 로 발동 입력을 만들어 재확인.
- 민감 열(사번·이름·전화)이 출력·로그에 없는지 `grep`. 보안 계약(열 화이트리스트·불일치 참조 `ValueError`·외부 실패 위장 금지) 중 해당 항목은 실제 FAIL 을 본 뒤 통과.

## ③ FAIL·트레이스백이면 재현 먼저
- 긴 출력은 종류별 `grep -c` 로 세고 시간순 첫 실패만 고른다(뒤따른 오류는 증상).
- 한 줄 재진술: 쉬운 말 1문장 + 의심 `파일:줄` + 전제(Python 버전·인코딩·시간대).
- 최소 재현 3행: 입력(헤더 포함)·명령·기대 vs 실제 표. 담당자 피드백이면 담당자 값과 우리 값을 나란히. 재현 입력은 `.tmp/<이름>/` 에만. 안 되면 `재현 불가 — 필요한 정보: ___` 로 멈춘다.
- 가역적 검사 순서: 입력 값 → 경계·결측·중복·형식 혼재 → 최근 변경(DECISIONS 4·`note.md`) → 환경. 원인 후보 3개 + 확인 명령 표, 프로브 1개. 추정은 `확인 필요`.
- 재현 테스트 `test_<규칙>_<상황>` 추가 → 먼저 FAIL → 수정 → PASS. 거부할 입력은 조용히 보정하지 않고 `ValueError`.

## ④ task 마감
- `python3 scripts/debug_dir.py NN_단계명` 폴더에 4파일. `verify.json` 키: stage·what·status·files·method·inputs·outputs·counts·samples·tests·notes. `--decisions NN_단계명` 으로 `decisions` 키 병합, `--check` exit 0.
- DECISIONS 1 결정 · 4 RED→FIX(증상·발견 경로·원인·맡긴 것/직접 한 것·조치·검증, 같은 종류 입력 1개 더) · 5 한계 · 6 검증 로그 각 1줄. 병렬 구간은 자기 work 파일 ⑤·⑥ 에 쓰고 CP 때 옮긴다.
- 'NN 끝' 행 = 결정 3·깨질 입력 3·재검증 1·바꾼 것 1(전/후와 이유), AGENTS 8절.
- `python3 scripts/docmap.py --check` exit 0 · PLAN 4 자기 행 상태 · 신호 task(PLAN 4-2)면 ⑦ `연결 N`.
- 보고: 표 `항목 | 상태 | 명령 | 출력 요약 | 파일:줄` + 5줄 요약(AGENTS 8절) + 꼬리 1줄(AGENTS 7절). FAIL·NOT_RUN 이면 다음 행동 1개.

## 규칙
- 결정적 테스트: 랜덤·현재 시각·네트워크·파일 순서 의존 금지. 값·행 수·예외를 assert(스냅샷 비교 금지).
- 테스트 수는 `tests/` 만 센다(`scripts/tests` 제외).
- 기대값의 반올림·tie-break 가 `# 결정:` 과 다르면 테스트가 아니라 결정을 먼저 맞춘다.

## 금지
- 표 승인 전 테스트 작성, 테스트와 구현을 같은 턴에, 재현 전 코드 수정, 테스트에 맞춘 하드코딩, assert 약화.
- 기존 테스트 수정·삭제(먼저 보고, AGENTS 1절 9). 사람 결정 없는 업무 규칙을 기대값으로 고정.
- 실행 안 한 것을 PASS 로, 전부 SKIP 을 통과로, 암산 숫자. `out/debug` 에 스냅샷·입력 복사본·브라우저 프로필.
