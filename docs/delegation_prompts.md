# 위임 프롬프트 모음 (복사해서 쓴다 · 대화 로그가 채점 표면이다)

모든 위임은 **목표 / 범위 / 제약 / 완료 조건 / 검증** 5요소 + 마지막 두 줄(결정 주석·테스트 변경 금지)을 갖춘다. 한 번에 한 가지. "전체를 만들어 줘" 금지. 구간별 예시 25개는 `docs/prompt_examples.md`(`python3 scripts/prompt.py <번호|키워드>` 로 터미널에 복사용 출력, 토큰 0).

## 0. 첫 프롬프트 (세션 시작)
```
AGENTS.md를 읽고 이 세션의 규약으로 써. 코드는 아직 쓰지 마.
TASK.md 머리에 `시작: HH:MM` 을 적고, 타이머 명령(python3 scripts/timer.py --start HH:MM --loop 300)을 첫 보고에 그대로 출력해.
README와 파일 목록, 데이터 형식, 제출물 형식을 읽고 TASK.md의 한 문장·P0·1~5번을 채워 보여줘.
업무 담당자에게 물어볼 질문 5~8개를 docs/stakeholder_interview.md 순서로 만들어. 번호를 붙이고 한 번호에 한 주제, 질문마다 괄호로 왜 묻는지 한 줄. 끝에 사용 가능한 스킬 이름을 한 줄로 덧붙여.
보고는 꼬리 3줄(지금 / 다음 추천 / 대기 중 할 일)로 끝내.
```

## 1. 데이터 첫 파악 (현미경)
```
python3 scripts/eda_bootstrap.py data/*.csv 를 실행하고 eda_summary.md만 읽어.
그룹 열(라인/공급사/기간)별 행 수·평균·최소·최대·결측률 표와 일별 추세 10줄, 단위·형식 혼재 의심 지점을 보고해. 해석은 하지 말고 사실만.
```

## 2. 규칙 하나 구현 (테스트 먼저)
```
[규칙 한 문장]을 구현해줘.
목표: ___ / 범위: ___ 함수만 / 제약: 표준 라이브러리, 입력 불변, 정렬·tie-break 명시
완료 조건: test____ 통과. 먼저 실패하는 테스트를 만들어 FAIL을 보여주고, 그다음 구현해.
검증: python3 -m unittest -v 와 규칙 발동 건수(제외·보정·거부) 보고.
테스트를 고치거나 지워야 하면 하지 말고 먼저 말해줘. 지시 안 한 걸 정해야 하면 그 자리에 # 결정: 주석을 달아줘.
```

## 3. 기능 끝난 뒤 캐내기 (매번)
```
grep -rn "결정:" src tests 결과를 표로 주고,
방금 코드에서 내가 지시 안 했는데 네가 정한 걸 전부 나열해줘. 각각 다르게 할 수 있었던 선택지도 같이. 코드는 고치지 마.
방금 쓴 코드를 5줄 이내 한국어로 설명해줘. 전문 용어 쓰지 말고. 지금 코드가 틀린 답을 낼 수 있는 입력을 3개만 말해줘.
결정이 필요한 것은 추측하지 말고 decisions/pending.md 형식(AGENTS.md 5절: 후보 2~4개·추천 1개·기본값·안 정하면 시각)으로 적어라.
```

## 4-1. 범위를 넓히는 요청 (새 지표·새 화면 — Codex 가 먼저 되묻는다, AGENTS.md 1절 10)
```
[새 지표/새 화면: 예) 공급사별 월간 추세 그래프]를 추가하고 싶어. 실행하기 전에 python3 scripts/next.py 를 보고 "남은 N분 중 약 M분 소요, 진행할까요?" 로 먼저 되물어. 80분이 지났으면 새 접근(라이브러리·구조 변경)은 안 한다고 같이 말해.
```
기대 응답: `남은 92분 중 약 25분 소요(규칙표 3/7 진행 중). 80분 경과라 새 라이브러리는 쓰지 않고 기존 solve() 에 열 1개 추가로 좁히면 15분. 진행할까요?` — 이 되묻기 없이 바로 시작하면 AGENTS.md 1절 10을 다시 읽힌다. "진행"이라고 답하면 TASK.md 4·5번을 먼저 고치게 한다.

## 5. 경계 입력·계약 검사
```
python3 scripts/make_edge_cases.py data/<주 파일>.csv --out data/edge/ 로 변형 파일을 만들고, 내 프로그램을 각 파일로 실행해 터지는지·조용히 틀리는지 표로 보고해.
scripts/check_contract.py의 RULES와 recompute_expected를 이 과제 규칙으로 채워(테스트와 독립적으로 재계산). 종료 코드 2는 통과가 아니다.
```

## 6. 웹 과제 (30분 렌더)
```

```

## 7. 동결 구간 문서
```
이 문서는 처음 보는 심사자가 5분 안에 읽는다. AI가 읽는 메모가 아니다. 결론을 먼저, 한국어로, 숫자를 넣고, 표를 써줘. 못 한 것도 숨기지 말고 써줘.
1) 지금 구현의 한계를 DECISIONS.md 5번에 써줘. 실제로 실행해서 확인한 것만. 확인 안 한 건 "확인하지 않은 것"으로 따로.
2) TASK.md의 빈칸을 지금 코드 기준으로 채워줘. 없는 건 없다고 써. 완료 조건은 실제 테스트 이름과 1:1로.
3) README.md를 다시 써줘: 한 문장 / 자동화한 것·안 한 것 / 실행 방법(실제로 되는 명령만) / 데모 순서(정상·실패) / 지금 상태(숫자) / 실제 vs 목업 / 내가 정한 것과 이유 / 못 한 것과 이유. 템플릿 문구가 남아 있으면 지워줘. 모든 주장에 파일:줄·테스트·실행 명령을 붙여줘.
```
