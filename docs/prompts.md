# 예시 프롬프트 27개 — 복사해 창에 붙인다

흐름: 1~3 인터뷰 → 4~7 PRD → 8~9 계획 → 10~13 시작(12 시안 선택) → 14~21 구현(14 연결 전달 · 27 핵심 알고리즘 후보) → 22 심사 → 23~25 동결·제출 · 26 막힘

## 쓰는 법

- 항목 제목은 줄 맨 앞 `[목표]`·`[수행]` 꼴, 아래는 번호 목록(1. 2. …). 항목은 상황 따라 2~4개, 직접 쓸 때도 같은 꼴. 스킬은 `$이름`.
- 빈칸은 문장 안의 `[ ]` 만 채우고, 해당 없는 줄·항목은 지운다. 붙일 창은 제목 괄호.
- 보고는 task 끝·결정 요청 때 꼬리 1줄(`python3 scripts/status.py` 출력 그대로). 꼬리 3줄·다음 추천은 요구하지 않고, 궁금하면 `STATE`.
- 하위 에이전트는 A 의 PLAN 4 `묶음 Pn` 만(work/README.md 8). B·C·포크는 금지: '병렬로 해줘' 대신 T2·T3 창을 열어 11·13 을 붙인다.
- 연결 신호와 번호 붙은 요청(`@A C1:`)은 창이 스스로 읽는다(`scripts/wait_signal.py`: task 끝마다 `--once`, 놀 때는 30초 간격). `status.py` 에 `연결 대기`·`요청 대기` 가 남을 때만 14 를 붙인다.
- PLAN 4 의 `(핵심)` task 는 A 가 코드 전에 27 로 후보 2~3개를 pending 에 올리고, 사람이 고른다(15). 그동안 A 는 다른 task.
- 서버는 Codex 가 띄우고 `[서버] 포트 8000 열었음 · 경로 / · 종료 kill <pid>` 1줄로 보고한다. 미리보기 탭에 포트 넣기와 `--freeze` 는 사람만.

## 1. 시작 신호 직후 — `$kickoff` (T1)

```text
[목표]
1. $kickoff — 시작 [ ] · 마감 [ ]. AGENTS.md 는 주입돼 있으니 다시 열지 말고, 코드는 아직 쓰지 마.
2. README·파일 목록·eda_bootstrap.py 요약으로 TASK 한 문장·P0·3절 질문 표. README 에 없는 것은 추측 말고 질문으로.
[질문]
1. docs/stakeholder_interview.md 카테고리 표대로 R 은 전부, 나머지는 행마다 0~3개(README 가 답하면 0), 한 코드에 한 주제.
2. 제외 목록(표기·식별자·IT·정답 자료·화면 배치)은 묻지 말고 pending 에 '불필요 — 데이터 결정'.
3. 첫 묶음(R+A+B+C 에서 3~4개)을 메신저 틀로: 코드(A1·B2) + 괄호 속 왜 묻나.
[출력]
1. 한 문장 목표·P0 미확인·질문 표 요약 + 꼬리 1줄.
```

막는 실수: README 를 다 읽기 전에 코드를 쓰거나, 표기·IT 질문으로 첫 묶음을 낭비하는 것.

## 2. 질문을 보내기 전 — 인터뷰 질문 다듬기 (T1)

```text
[수정]
1. [ ] 번은 제외 목록이니 빼고 pending 에 '불필요 — 데이터 결정' 으로.
2. 열 이름·구현 용어·해법 제안이 든 질문은 업무 말(경계·제외·중복·단위)로 다시 써.
[검증]
1. 질문마다 3줄 검사(엑셀로 할 때 내가 정할 일인가 / README 에 있나 / 이미 받은 답인가), 하나라도 '예'면 지워.
2. PRD 빈칸(6 업무 규칙·9 가정)을 채우지 않는 질문도 지워.
[출력]
1. 남은 질문을 docs/stakeholder_interview.md 3절 메신저 틀로, 묶음당 3~4개.
```

막는 실수: "정답 목록을 보내 주세요"·"대소문자가 달라도 같은 장비인가요" 같은 답할 수 없는 질문을 보내는 것.

## 4. 답을 다 옮긴 뒤 — PRD 초안 `$prd` (T1)

```text

[출력]
```

막는 실수: 답이 TASK 표에 흩어진 채 요구사항 원본 없이 task 를 나누는 것.

## 5. PRD 초안을 읽고 — 검토 피드백·담당자용 5줄 (T1)

## 7. 승인 뒤 담당자 답이 바뀌면 — `요구사항 갱신:` + `$prd 갱신` (T1)

```text
[요구사항 갱신]
1. 요구사항 갱신: [ ] (출처: 담당자 [ ] "[ ]")
[수행]
```

막는 실수: '경계값도 포함' 같은 바뀐 답이 대화에만 남고 테스트보다 코드가 먼저 바뀌는 것.


## 9. task 표를 읽고 — 표 수정·승인 = CP0 (T1)

```text
[수정]
1. [ ]번 task 는 [ ] (둘로 나눔·담당 변경·생략 후보로 뒤로).
[연결 표 검토]
1. 다른 담당을 기다리는 task 마다 신호 1행이 있고, 같은 신호가 두 행으로 나뉘지 않았나.
```

막는 실수: 표 승인을 업무 규칙 결정으로 착각해 대기 중인 Dnn 을 기본값으로 구현하는 것.
