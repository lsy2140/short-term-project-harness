# 심사 시뮬레이션 — T4 read-only 창 1회

- 목적: 제출 전에 바깥 심사자처럼 내 산출물을 채점받아, 증거가 없는 항목을 메운다.
- 스킬이 아니다. 사람이 새 창 T4 를 열고 아래 프롬프트를 붙여넣는다.
- 구현 창(T1~T3)에 묻지 않는다. 같은 세션은 자기 결정을 변호한다.
- PLAN·work 는 가린다. 계획과 같은 가정을 공유하지 않고 제출물만으로 판단하게 하려는 것이다.

## 1. 언제·어디서

| 조건 | 무엇을 | 창 |
|---|---|---|
| CP2 통합 뒤(전체 테스트·check_contract 통과, 사람이 `--freeze` 를 찍음) | 전체 채점 1회(2절) | T4 `cd <과제 폴더> && codex -s read-only` |
| 동결 선언 뒤 문서 정리를 마쳤을 때(선택) | 근거(파일:줄) 누락만(3절) | 같은 T4 창 |

- 결과를 받으면 T4 는 닫는다. 보완은 담당 창에 `docs/prompts.md` 16(CP 재개)으로 미충족 2개를 전달한다.

## 2. 전체 채점 프롬프트

```
너는 과제 플랫폼의 AI 심사자다. 코드를 고치지 마라. 표로만 답하고 칭찬·총평은 쓰지 마라.
읽는 것: README.md · PRD.md · TASK.md · DECISIONS.md · HANDOFF.md · tests/ · 진입점 코드 1~2개
· out/debug/*/green.txt · out/report/.
PLAN.md 와 work/ 는 읽지 마라(제출물만으로 판단하게 하려고 일부러 가렸다). 데이터 파일도 읽지 마라.
실행은 읽기 명령과 `python3 scripts/preflight.py --check-freeze` 만 — freeze 뒤 tests/ 가 승인 없이 약해지거나 지워졌는지 본다.
아래 14개 항목과 소통 1개를 채점해라. 열: 축 | 항목 | 판정(충족/부분충족/미충족) | 판정문 1줄 | 근거(파일:줄·테스트 이름·실행 명령) | 보완 행동 1개.
근거를 못 찾으면 그 칸에 "근거 없음" 이라 쓰고, 보완 행동은 task 1개 안에 끝나는 크기로 적어라.
기술: 코드 유지보수성 / 요구사항 충족도 / 기능적 정확성 / 실무적 품질 위험(비밀키·입력 보호·예외) / 제출물 완성도
의도: Output 목표 구체화 / 재사용 가능한 작업 체계 / 의도 갱신 및 맥락 유지 / 검증 루프 설계·통제 / 문제 상황·제약 정의 / 작업 분해·위임 설계
인지: AI 산출물 동작·리스크 예측 / AI 산출물 구조 이해 / AI 의사결정·근거 이해
소통: 다른 사람이 이어갈 수 있는가(HANDOFF·README 실행 방법·DECISIONS 4 기록)
마지막에 가장 약한 항목 2개를 반드시 골라라. 이어서 문서의 주장 중 코드·테스트·실행 기록으로 뒷받침되지 않는 문장을 파일:줄과 함께 나열해라.
```

## 3. 근거(파일:줄) 누락만 (선택)

```
README.md·DECISIONS.md·HANDOFF.md 에서 근거(파일:줄·테스트·실행 명령)가 없는 주장만 `파일:줄 — 문장 요약` 으로 나열해라.
코드는 고치지 마라. PLAN.md 와 work/ 는 읽지 마라.
```

## 4. 14항목과 이 키트에서 증거가 있는 곳

| 축 | 항목 | 증거가 있는 곳 |
|---|---|---|
| 기술 | 코드 유지보수성 | `docmap.py --check` · 단계 = 모듈 = 테스트 파일 |
| 기술 | 요구사항 충족도 | PRD 5 MUST ↔ TASK 5 완료 조건 ↔ 테스트 1:1 |
| 기술 | 기능적 정확성 | `unittest` 숫자 · `check_contract.py` · `out/report/stage_NN.md` 재계산 |
| 기술 | 실무적 품질 위험 | 입력 검증·예외 테스트 · preflight secret 검사 |
| 기술 | 제출물 완성도 | `preflight.py --require` exit 0 · README 가 정한 이름·형식 그대로 |
| 의도 | Output 목표 구체화 | TASK 한 문장·5 완료 조건 · PRD 2 목표·5 기능(+DECISIONS 0 확인 기록) |
| 의도 | 재사용 가능한 작업 체계 | AGENTS.md · 스킬 6개 · `scripts/` |
| 의도 | 의도 갱신 및 맥락 유지 | PRD 10절 변경 이력(+DECISIONS 0 시각) · `요구사항 갱신:` 원문 |
| 의도 | 검증 루프 설계·통제 | `out/debug/NN_*/red.txt` → `green.txt` · `--check-freeze` |
| 의도 | 문제 상황·제약 정의 | PRD 3 범위·6 업무 규칙·9 가정 |
| 의도 | 작업 분해·위임 설계 | README·HANDOFF 3 구조 표에 드러난 담당 분리(심사에서는 PLAN·work 를 가림) |
| 인지 | AI 산출물 동작·리스크 예측 | DECISIONS 5 깨질 입력 · HANDOFF 5 믿지 말 것 |
| 인지 | AI 산출물 구조 이해 | HANDOFF 3 구조 표 · 종합정리 '부분별 설계 이유' |
| 인지 | AI 의사결정·근거 이해 | DECISIONS 1 결정표(결정자 열) · `# 결정:` 주석 |
| 소통 | 이어갈 수 있는가 | HANDOFF · README 실행 방법 · DECISIONS 4 RED→FIX |

## 5. 결과를 쓰는 법

| 판정 | 할 일 |
|---|---|
| 미충족(의도) | 다음 위임 프롬프트에 목표·범위·제약·완료 조건·검증을 적어, 로그와 PLAN 8 에 남긴다 |
| 미충족(인지) | DECISIONS 1·5 에 결정·이유·깨질 입력을 더한다 → 종합정리 재료 |
| 미충족(기술) | 테스트 추가 또는 한계로 기록(동결 선언 뒤면 기록만) |
| PLAN·work 를 가려서 생긴 근거 없음 | README 에 `PLAN.md` 4·4-2·8 링크 1줄(실제 심사자는 PLAN 도 본다) |
| 근거 없음 | 문장 옆에 근거(파일:줄)를 붙인다. 못 붙이는 문장은 지운다 |

- 결과는 참고다. 실제 심사자는 대화 로그 전체와 토큰 사용량도 본다.
- "훌륭하다" 는 의심한다. 가장 약한 2개는 반드시 받는다.
- 설명이 막힌 항목은 `docs/implementation_summary.md` '설명이 막힌 항목' 표에 쌓는다.
