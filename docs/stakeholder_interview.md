# 업무 담당자(가상 이해관계자) 인터뷰 가이드

첫 20분의 질문 품질이 "의도 관리" 점수를 결정한다. 해법 단어(자동화·AI·대시보드·모델) 대신 **업무 사실**을 묻는다.

## 순서와 예시 문장
| 단계 | 목적 | 예시 질문 |
|---|---|---|
| ① 에피소드 | 실제 상황 파악 | "최근에 이 일이 문제가 된 사례를 하나만 구체적으로 알려 주세요. 언제, 누가, 어떤 데이터로요?" |
| ② 워크어라운드 | 현재 처리 방식 | "지금은 어떻게 처리하고 계세요? 엑셀? 수작업? 몇 분 걸리나요? 누가 하나요?" |
| ③ 정량화 | 성공 기준 | "잘됐다는 걸 어떤 숫자로 아시나요? 현재 값은 얼마고 어디서 측정되나요?" |
| ④ 비용·당사자 | 우선순위 | "이게 안 풀리면 누가, 얼마나 손해인가요? 가장 급한 건 무엇인가요?" |
| ⑤ 경계·예외 | 규칙 확정 | "제외해야 하는 경우가 있나요? 기준값과 같으면 포함인가요? 단위·시간대는요? 중복은 어떻게 보나요?" |
| ⑤-1 절대 금지 | 가드레일 스펙 | "절대 나가면 안 되는 결과는 무엇인가요? 그게 나가면 누가 어떤 손해를 보나요?" |
| ⑤-2 실패 시 표시 | 폴백 스펙 | "처리가 실패하거나 느리거나 데이터가 없을 때 화면·파일에 무엇을 보여야 하나요?" |
| ⑤-3 자동화 단계 | 범위 좁히기 | "이 업무는 몇 단계로 이루어지나요? 이번에 자동화할 단계는 어디까지인가요?" |
| ⑤-4 응답 모양 | 출력 형식 확정 | "결과 화면·API·파일은 목록만 있으면 되나요, 건수·요약이 같이 붙나요? 열 순서는요?" (리허설 1 W3 WARN 의 원인) |
| ⑥ 산출물 | 형식 확정 | "결과는 어떤 형태로 받고 싶으세요? 누가 열어 보나요? 꼭 들어가야 할 열·정렬이 있나요?" |
| ⑦ 합의 | 확인 | "제가 이해한 내용입니다: 문제/원인/성공 기준/만들 것·안 만들 것/제약. 맞나요?" |

## 기법
- 답을 받으면 한 번 더 파고든다: "그 경우는 어떻게 되나요?", "예외가 또 있나요?"
- **첫 질의는 5~8개를 번호를 붙여 한 메시지로.** 한 번호에 한 주제, 질문마다 괄호로 왜 묻는지 한 줄(예: "…인가요? (경계값 처리를 정하려고요)"). 이후 되묻기는 1~2개씩(번호 `N-1`, `N-2`).
- **주의: 담당자 AI 는 묶음 질문에 하나만 답할 수 있다.** 리허설 1에서 3개를 한 메시지에 묶어 되묻기가 늘었다. 한 번호에 둘을 넣지 않는다.
- 답변은 `답변 N:` 번호로 돌려받아 TASK.md 3번 표에 번호로 매핑한다(질문 번호 = 답변 번호, 시각 기록). TASK.md 3번의 기본 8행은 한 번호 한 주제로 `docs/prompt_examples.md` 5번과 같은 순서다 — README 에 답이 있는 행은 지우고 과제 값을 채운 뒤 번호를 다시 매겨 5~8개로 보낸다. 복사용 메시지 틀: `python3 scripts/prompt.py 5`(docs/prompt_examples.md 5번).
- "할 일 목록을 알려 주세요"는 막힌다. 업무를 짚어 묻는다. 담당자 AI는 README 범위를 크게 벗어나지 않고 유도신문에 저항한다(공개 후기 실측).
- 담당자가 "모른다/담당 아님"이라고 하면 가정으로 기록하고 틀렸을 때 영향을 적는다.
- 합의문을 보내 확인받은 시각을 DECISIONS.md 0번에 적는다. 이 기록이 서술형 "의도" 문항의 근거가 된다.

## 합의문 골격 (구현 착수 전 필수)
```
문제:
왜 생기나(병목):
성공 기준: 숫자 / 현재값 / 측정처
만들 것:
안 만들 것:
제약(제외·경계·단위·시간대·형식):
```

## 자주 숨어 있는 조건 (반드시 확인)
취소·무효·퇴사·단종 같은 **제외 대상** / 경계값 포함 여부 / 단위(개·박스, 원·천원) / 시간대·기준일 / 중복·최신 우선 규칙 / 정렬·tie-break / 결측 처리 / 결과를 보는 사람과 빈도 / 보안·개인정보 제약
