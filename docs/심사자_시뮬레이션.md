# 심사자 시뮬레이션 — 두 번째 Codex 세션으로 3축 채점 받기

이 형식의 과제 채점은 AI 심사자가 코드·대화 로그·테스트 결과를 읽고 항목별로 충족/부분충족 배지, 판정문, 증거 좌표를 남기는 방식이다(같은 플랫폼 공개 후기). 제출 전에 같은 방식으로 **내 산출물을 한 번 채점받아** 증거가 없는 항목을 메운다.

## 언제·얼마나
- **130분**: 전체 채점 1회 (아래 프롬프트). 결과에서 "부분충족·미충족" 항목만 보완.
- **165분**: "증거 좌표 누락만" 재점검 (짧은 프롬프트).
- 토큰을 쓰므로 2회만. 긴 파일은 읽히지 말고 README·PLAN·DECISIONS·테스트 결과만.

## 실행
```bash
# 새 터미널에서 (read-only 세션)
cd <과제폴더> && codex -s read-only
```
프롬프트(붙여넣기, 또는 `$probe-judge`):
```
너는 과제 플랫폼의 AI 심사자다. 이 저장소의 README.md, PLAN.md, DECISIONS.md, TASK.md, HANDOFF.md, tests/, 핵심 코드만 읽고
아래 14개 항목을 채점해라. 항목마다 [충족 / 부분충족 / 미충족] + 판정문 1줄 + 증거 좌표(파일:줄 또는 테스트 이름 또는 실행 명령) 를 적어라.
증거를 찾지 못하면 "증거 없음"이라 쓰고, 보완에 필요한 가장 작은 행동 1개를 제안해라. 코드를 고치지 마라. 표로만 답해라.

기술: 코드 유지보수성 / 요구사항 충족도 / 기능적 정확성 / 실무적 품질 위험(비밀키·입력 보호·예외) / 제출물 완성도
의도: Output 목표 구체화 / 재사용 가능한 작업 체계 / 의도 갱신 및 맥락 유지 / 검증 루프 설계·통제 / 문제 상황·제약 정의 / 작업 분해·위임 설계
인지: AI 산출물 동작·리스크 예측 / AI 산출물 구조 이해 / AI 의사결정·근거 이해
소통: 다른 사람이 이어갈 수 있는가(HANDOFF·README 실행 방법·DECISIONS 4번 기록)
추가 확인: `python3 scripts/preflight.py --check-freeze` 로 1차 동결 이후 tests/ 가 약화·삭제됐는지(변경이 있으면 DECISIONS 에 승인 기록이 있어야 한다).
```
165분 재점검 프롬프트:
```
README.md·PLAN.md·DECISIONS.md에서 증거 좌표(파일:줄/테스트/실행 명령)가 없는 주장만 줄 번호와 함께 나열해라. 코드는 고치지 마라.
```

## 결과를 쓰는 법
| 판정 | 할 일 |
|---|---|
| 미충족(의도) | 해당 요소가 **대화 로그**에 남도록 다음 위임 프롬프트에 목표·범위·제약·완료 조건·검증을 명시 |
| 미충족(인지) | DECISIONS.md 1·5번에 결정·이유·깨지는 입력 추가, 서술형 답변 재료로 |
| 미충족(기술) | 테스트 추가 또는 한계로 기록(144분 이후면 기록만) |
| 증거 없음 | 문서 문장 옆에 좌표 추가. 좌표를 못 붙이는 문장은 삭제 |

## 주의
- 시뮬레이션 결과는 **참고**다. 실제 심사자는 대화 로그 전체와 토큰 사용량도 본다.
- 심사자 세션이 "훌륭하다"고 하면 의심한다. 반드시 미충족 항목을 최소 2개 내게 한다("가장 약한 항목 2개를 반드시 골라라").
